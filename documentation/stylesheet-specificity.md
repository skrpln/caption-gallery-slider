# Stylesheet Specificity

Связанные заметки: [[documentation/architecture]], [[documentation/release-pipeline]], [[progress_log]]

`styles.css` не содержит ни одного `!important`. Автоматический scorecard каталога сообщества считает каждое вхождение отдельным warning: релиз `0.1.3` получил 30 таких замечаний. Заметка фиксирует, чем `!important` заменён и какую ошибку легко совершить при его снятии.

## Что приходится переигрывать

Порядок загрузки в Obsidian: `app.css` → стили плагинов → тема → сниппеты. Плагин конкурирует с двумя источниками:

- `app.css` — правила вида `button` (0,0,1) и `button:hover` (0,1,1), а для панели подписи `.markdown-rendered p` (0,1,1);
- тема сообщества грузится **после** плагина, поэтому при равной специфичности выигрывает она. Типичное правило темы — `body.theme-dark .markdown-rendered p` (0,2,2).

## Приёмы вместо `!important`

| Задача | Решение | Специфичность |
| ------ | ------- | ------------- |
| Переиграть голое `button` из `app.css` | цепочка от корня плюс тег: `.og-gallery button.og-gallery__arrow` | (0,2,1) |
| Модификатор поверх базового правила кнопки | обе класса на элементе: `.og-gallery button.og-gallery__arrow.og-gallery__arrow--previous` | (0,3,1) |
| Состояние корня скрывает кнопку | `.og-gallery.og-gallery--view-fit button.og-gallery__crop-zoom` | (0,3,1) |
| Сбросить типографику блоков подписи поверх темы | полная цепочка плюс `:is(...)`: `.og-gallery .og-gallery__caption .og-gallery__caption-content :is(p, ul, …, .markdown-preview-section > div)` | (0,4,1) |
| Один курсор на всю панель во время drag | CSS-переменная, см. ниже | — |

`:is()` берёт специфичность самого «тяжёлого» аргумента, поэтому один селектор закрывает и теги (`p`), и классы обёрток Obsidian (`.el-p`), и вложенный `.markdown-preview-section > div`.

## `--og-cursor`

Курсор во время перетаскивания раньше задавался как `.og-gallery.is-resizing * { cursor: ns-resize !important }`. Универсальный селектор даёт (0,2,0) и проигрывает собственным правилам кнопок (0,2,1), поэтому без `!important` он не работал.

Сейчас каждое объявление курсора читает переменную с fallback на своё обычное значение:

```css
.og-gallery__viewport { cursor: var(--og-cursor, pointer); }
.og-gallery__caption-content { cursor: var(--og-cursor, text); }
.og-gallery__resize-handle { cursor: var(--og-cursor, ns-resize); }
```

Состояние объявляет переменную один раз на корне:

```css
.og-gallery.is-resizing {
  --og-cursor: ns-resize;

  cursor: ns-resize;
}
```

Переменная наследуется, поэтому её видят все потомки независимо от специфичности своих правил. Прямое `cursor: ns-resize` на корне нужно для элементов, которые своего курсора не объявляют: `cursor` — наследуемое свойство.

Состояния `is-crop-zooming` и `is-crop-dragging` переменную не ставят: их селекторы (0,2,0) и так выигрывают у `.og-gallery__viewport` (0,1,0). Они тоже читают `var(--og-cursor, …)`, чтобы resize имел приоритет над crop.

## Ловушка при снятии `!important`

`!important` подавляет не только правила с меньшей специфичностью, но и правила с **большей**, которые целятся в то же свойство. Снятие `!important` их оживляет.

Реальный случай из этой работы: базовая рамка стрелок стояла как `border: 1px solid … !important` (0,2,1) и глушила `border-color: var(--interactive-accent)` в правиле `.og-gallery button.og-gallery__arrow:hover` (0,3,1). После снятия `!important` акцентная рамка появилась при наведении — причём только на тех гранях, которые модификаторы `--previous` и `--next` не обнуляют. Объявление оказалось мёртвым для всех остальных элементов своего селекторного списка (у `fullscreen`, `crop-zoom`, `rotate`, `video-button` стоит `border: 0`, у ползунков рамки нет) и было удалено. При наведении на стрелки меняется только `opacity`, 0.72 → 0.94.

Правило: убирая `!important`, проверяй не только «что оно перебивало», но и «что оно скрывало».

## Проверка каскада без Obsidian

Статический стенд: `app.css`-заглушка, затем `styles.css`, затем таблица «темы» с более высокой специфичностью; в теле — разметка галереи и проверки через `getComputedStyle`. Отдаётся `python3 -m http.server`, открывается по `http://localhost:<port>` (вкладка `file://` в панели браузера скриптов не выполняет).

Стенд ловит три класса ошибок: правило не распарсилось (сравнить `document.styleSheets[i].cssRules.length` до и после правки), тема перебивает плагин, состояние (`is-resizing`, `is-crop-*`, `is-hidden`) не даёт ожидаемого `computed style`.
